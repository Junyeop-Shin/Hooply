# 06. 배지 체계

기록 탭의 배지를 **어떻게 나누고, 어떻게 그리고, 어떻게 고치는지** 정리한 문서입니다.
아이콘 파일은 [badges/svg/](badges/svg/)에, 전체 미리보기는 [badges/preview.html](badges/preview.html)(브라우저로 열기)에 있습니다.

## 1. 원칙

- **배지는 실력을 겨루지 않는다.** 팀 가입·설문·참석·출전·투표처럼 함께한 **행동**만 센다. 실력 등급 배지는 만들지 않는다.
- **자랑·공유·획득 알림은 없다.** 기록 탭을 열면 서버가 그때 판정하고, 얻은 배지는 칸 색이 바뀌는 것으로 끝난다.
- **한 번 얻은 배지는 회수하지 않는다.** 기준을 나중에 올려도 이미 얻은 배지는 남는다.
- **사용자 단위로 센다.** 여러 팀을 다니면 모든 팀의 기록을 합친다. 나로 병합된 게스트 시절 기록도 포함한다.

## 2. 묶음 배지와 단일 배지

같은 행동을 쌓는 배지는 **묶음**으로 묶어 한 칸에서 동 → 은 → 금으로 올라간다. 한 번이면 끝나는 배지는 **단일** 칸이다.
서버에는 배지 20개가 있고, 화면에는 칸 12개가 보인다.

### 묶음 4개 (각 동·은·금)

| 칸 이름 | 묶음 키 | 그림 | 동 | 은 | 금 | 서버 코드 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| 출전 | `QUARTERS` | 농구공 | 10쿼터 | 50쿼터 | 100쿼터 | `QUARTERS_10` · `QUARTERS_50` · `QUARTERS_100` |
| 참석 | `ATTEND` | 달력 + 체크 | 5회 | 10회 | 25회 | `ATTEND_5` · `ATTEND_10` · `ATTEND_25` |
| 투표 | `VOTES` | 투표함 + 용지 | 1회 | 5회 | 10회 | `FIRST_VOTE` · `VOTES_5` · `VOTES_10` |
| 동료 지목 | `PLAY_AGAIN` | 두 사람 + 하트 | 1회 | 5회 | 10회 | `PLAY_AGAIN_1` · `PLAY_AGAIN_5` · `PLAY_AGAIN_10` |

"동료 지목"은 경기 후 투표에서 **"다음에 같이 뛰고 싶은 사람"으로 지목받은** 횟수다.

### 단일 8개

| 묶음 | 칸 이름 | 그림 | 얻는 조건 | 서버 코드 |
| --- | --- | --- | --- | --- |
| 시작 | 첫 팀 | 유니폼(번호 1) | 팀 코드로 팀에 들어온다 | `JOIN_TEAM` |
| 시작 | 설문 완료 | 클립보드 + 체크 | 실력·포지션 설문을 마친다 | `SURVEY_DONE` |
| 시작 | 내 위치 응답 | 순위 막대 3개 + 핀 | 동호회 안 내 실력 위치를 답한다 | `SELF_RANK_DONE` |
| 시작 | 첫 참석 응답 | 말풍선 + 체크 | 일정에 참석/불참을 처음 답한다 | `FIRST_RSVP` |
| 활동 | 첫 출전 | 농구화 | 쿼터 기록에 처음 이름이 오른다 | `FIRST_QUARTER` |
| 활동 | 연속 참석 | 불꽃 | 한 팀 일정에 3번 연속 나온다 | `STREAK_3` |
| 관계 | 서로 뽑은 사이 | 두 사람 + 양방향 화살표 | 서로 지목한 사람이 3명이 된다 | `MUTUAL_3` |
| 관계 | 게스트 영입 | 사람 + 플러스 | 내가 부른 게스트가 가입해 기록을 이어받는다 | `GUEST_CONVERTED` |

묶음(시작/활동/관계)마다 칸이 4개라 기록 탭에서 한 줄씩 빈자리 없이 채워진다. **칸을 추가할 때도 줄마다 4칸을 유지**하는 편이 좋다.

## 3. 화면 규칙

| 상태 | 칸 이름 | 아래 줄 | 틀 |
| --- | --- | --- | --- |
| 단일 · 얻음 | 칸 이름 | 얻은 날짜 `9/26` | 단일 |
| 단일 · 아직 | 칸 이름 | 여러 번 모으는 배지는 `2/3`, 아니면 `아직` | 잠김 |
| 묶음 · 아직 동도 없음 | 칸 이름 | `동까지 3/10` | 잠김 |
| 묶음 · 동 또는 은 | `출전 · 은` | `금까지 53/100` | 동 / 은 |
| 묶음 · 금 | `동료 지목 · 금` | `금 · 9/26` | 금 |

- 섹션 제목 옆 `획득 14/20`은 **칸이 아니라 배지(단계) 기준**으로 센다. 묶음 4개 × 3단계 + 단일 8개 = 20.
- 칸을 누르면 아래에서 시트가 올라온다(게스트 초대 시트와 같은 모양). 묶음은 동·은·금 세 줄에 얻은 날짜 또는 진행 막대를, 단일은 한 줄을 보여 준다.

## 4. 아이콘 디자인

아이콘은 **틀 5종 × 그림 12종**의 조합이다. 틀은 단계를, 그림은 무엇을 모으는지를 말한다. 그림은 단계가 바뀌어도 그대로다.

### 틀 5종

| 틀 | 모양 | 파일 |
| --- | --- | --- |
| 잠김 | 회색 원. 그림은 흐린 흑백(grayscale + 투명도 0.42) | [_frame-locked.svg](badges/svg/_frame-locked.svg) |
| 단일 | 앱 오렌지 원 + 가는 흰 안쪽 선 | [_frame-single.svg](badges/svg/_frame-single.svg) |
| 동 | 청동 원 + 가는 안쪽 선 | [_frame-bronze.svg](badges/svg/_frame-bronze.svg) |
| 은 | 톱니 테 + 안쪽 테 + 흰 구슬 16개 | [_frame-silver.svg](badges/svg/_frame-silver.svg) |
| 금 | 톱니 테 + 안쪽 테 + 구슬 20개 + 양옆 월계수 + 위쪽 별 + 뒤쪽 빛살 12줄 + 반짝임 | [_frame-gold.svg](badges/svg/_frame-gold.svg) |

**단계는 색만이 아니라 장식 개수로도 구분된다.** 색을 구분하기 어려운 사람도, 28px 크기에서도 동·은·금이 보이게 하기 위해서다. 리본은 쓰지 않는다(작은 크기에서 지저분해 보였다).

### 그림 규칙

- 지름 20 원 안에 들어가는 평면 아이콘. 3D·그림자·광택 없음. 글자·숫자 없음(유니폼 번호 1만 예외)
- **네이비 외곽선 1.5 + 면 채움 + 오렌지 포인트 하나.** 한 그림에 오렌지는 한 곳만 쓴다(체크 표시, 하트, 플러스 등)
- 모든 그림이 같은 선 두께와 같은 밀도로, 한 세트처럼 보여야 한다

### 색

앱 `index.css` 토큰과 같은 값이다. 금속 색은 틀에만 쓴다.

| 용도 | 값 |
| --- | --- |
| 오렌지 / 밝은 오렌지 | `#f26b1d` / `#ffa66b` |
| 네이비 / 중간 / 옅은 | `#14213d` / `#3d5480` / `#e0e6f0`, `#c2cde0` |
| 노랑 (불꽃 속·별) | `#f5c542` |
| 동 | `#e8b184` → `#c47a45` → `#8f4f25` |
| 은 | `#f4f6fa` → `#aeb8c8` → `#6f7d95` |
| 금 | `#fde9a8` → `#e8a92c` → `#b37a10` |

잠김 틀의 회색은 앱에서 화면 토큰(`--color-line`, `--color-sunken`)을 따라가서 어두운 화면에서도 자연스럽다. 단독 SVG 파일에는 밝은 화면 값이 고정으로 들어 있다.

### 좌표

- `viewBox="0 0 64 64"`, 메달 중심 (32, 32), 바깥 테 반지름 약 19.6, 흰 원판 반지름 14.2
- 그림은 (32, 27)을 중심으로 그렸고, 조합할 때 `translate(0 5)`로 메달 중심에 맞춘다
- 금 틀의 빛살·월계수는 반지름 31까지 나가므로 viewBox를 줄이지 않는다

## 5. 파일과 고치는 방법

| 파일 | 역할 | 손으로 고치나 |
| --- | --- | --- |
| [badges/badge_art.py](badges/badge_art.py) | **원본.** 색, 틀 5종, 그림 12종, 칸 목록 | ○ 여기만 고친다 |
| `frontend/src/components/badge-art.ts` | 앱이 쓰는 SVG 조각 | ✕ 자동 생성 |
| [badges/svg/](badges/svg/) | 배지마다 완성된 SVG 37개 (틀 5 + 단일 8×2 + 묶음 4×4) | ✕ 자동 생성 |
| [badges/preview.html](badges/preview.html) | 전체 미리보기 | ✕ 자동 생성 |
| `frontend/src/components/badge-icon.tsx` | 틀 + 그림을 조합하는 `BadgeIcon`, 그라데이션을 한 번 그리는 `BadgeDefs` | 조합 방식을 바꿀 때만 |
| `frontend/src/components/records.tsx` | 칸 묶기, 칸 문구, 단계 시트 | 화면 규칙을 바꿀 때만 |
| `backend/app/services/badge_service.py` | 배지 코드·기준·묶음·단계 (`BADGES`) | 기준을 바꿀 때 |

### 그림을 고치거나 바꿀 때

1. `docs/badges/badge_art.py`의 `PICTS`에서 해당 그림의 SVG 조각을 고친다
2. 실행한다

   ```
   python3 docs/badges/badge_art.py
   ```

3. `docs/badges/preview.html`을 브라우저로 열어 확인하고, 앱을 다시 빌드한다

### 배지를 새로 추가할 때

1. **서버:** `badge_service.py`의 `BADGES`에 한 줄 추가한다. 묶음이면 `series`와 `tier`를 적는다. 새 행동을 세야 하면 `counters()`에 지표를 더한다
2. **그림:** `badge_art.py`의 `PICTS`에 그림을 추가하고, 단일이면 `SINGLES`, 묶음이면 `SERIES`에 한 줄 추가한다
3. `python3 docs/badges/badge_art.py`를 실행한다
4. 이 문서의 표를 갱신한다

DB는 바꿀 필요가 없다. `user_badges`는 획득한 코드와 시각만 저장한다.

### 기준(쿼터 수·횟수)만 바꿀 때

`badge_service.py`의 `threshold`만 고친다. 이미 얻은 배지는 남는다.

## 6. 다른 도구로 다시 그리게 할 때

그림을 디자이너나 다른 AI에게 맡길 때는 아래 조건을 그대로 전하면 된다. 결과는 PNG가 아니라 **SVG 조각**으로 받아 `badge_art.py`의 `PICTS`에 넣는다.

```
결과물: 인라인 SVG 조각. viewBox 0 0 64 64 기준, (32,27) 중심, 지름 20 원 안. 글자 없음.
스타일: 평면 아이콘. 네이비(#14213d) 외곽선 1.5 + 면 채움 + 오렌지(#f26b1d) 포인트 한 곳.
       3D·그림자·광택·네온·무지개색 금지. 12개가 한 세트처럼 같은 선 두께와 밀도.
크기: 기록 탭에서 28~40px로 보인다. 그 크기에서 무엇인지 알아볼 수 있어야 한다.
틀은 그리지 않는다(앱이 잠김·단일·동·은·금 틀을 따로 씌운다).
```
