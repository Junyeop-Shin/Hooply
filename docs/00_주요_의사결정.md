# 주요 의사결정 — 무엇을, 왜 그렇게 정했나

> 설계하면서 내린 판단을 "상황 / 선택지 / 결정 / 근거 데이터 / 결과"로 정리했습니다.
> 수치는 모두 기존 문서에 적힌 값 그대로이고, 결정마다 출처를 달았습니다. 수치 근거가 없는 결정은 "수치 근거 없음"이라고 적었습니다.

**자주 나오는 말**

- **시뮬레이션** — 실력을 미리 정해 둔 가상 동호회(30명)를 만들어 몇 달치 모임을 컴퓨터로 돌려 보고, 우리 방법이 그 실력을 얼마나 맞히는지 재는 실험 (`backend/scripts/simulate_rating.py`)
- **순위 상관** — 두 순위가 얼마나 같은 순서인지 나타내는 값. 1이면 완전히 같고 0이면 관계없음
- **코트 마진** — 그 선수가 코트에 있던 동안의 "우리 팀 점수 − 상대 팀 점수"

## 한눈에 보기

| # | 결정 | 핵심 근거 |
| --- | --- | --- |
| 1 | 실력 지표: 점수 차 누적 → **예상 대비 초과분(잔차)** 누적 | 앱 조건 시뮬레이션에서 실력과의 순위 상관 0.61 → 0.89 |
| 2 | 케미: 경기 기록으로 **측정하지 않고** 경기 후 투표로 받는다 | 믿을 만하게 재려면 두 사람이 함께 60~90쿼터(주 1회로 3년 이상) 필요 |
| 3 | 같은 팀 묶기: 벌점이 아니라 **묶음을 한 덩어리로** 탐색 | 벌점은 실력 우선 전략에서 깨질 수 있음, 자동 테스트로 항상 지켜짐 확인 |
| 4 | AI 에게 역할 **판단은 맡기지 않고 설명만** | 일치율 AI 64% · 규칙 65%로 같음 → 규칙 보강 후 82% |
| 5 | 로테이션 자동 제안은 **범위에서 제외** | 수치 근거 없음 — 기록을 경기 후에 입력하는 운영 방식과 맞지 않음 |
| 6 | 매니저가 팀원 **실력 순서를 한 번 매기게** 한다 | 사전값 정확도를 0.5 → 0.8로 올리면 첫날 팀 균형 36% 개선 |
| 7 | 데이터를 위해 **운영 방식을 바꾸라고 하지 않는다** (팀 하루 고정 유지) | 20회 모임 기준 순위 상관 0.81 대 0.85로 손해가 작음 |
| 8 | **3팀**까지 지원 (16명 이상이면 매니저가 선택) | 지역 탐색이 완전 탐색 최적과 60건 중 60건 같음, 21명 약 0.1초 |
| 9 | 실력은 **수치 대신 등급**, 등급은 **팀 안의 위치**로 | 수치 근거 없음 — 기획 단계에서 찾은 "실력 공개 갈등" 위험 대응 |

## 1. 실력 지표를 점수 차 누적에서 "예상 대비 초과분"으로

| 항목 | 내용 |
| --- | --- |
| **상황** | 개인 스탯 없이 쿼터별 점수와 출전 5명만 기록한다. 이 기록으로 실력을 매겨야 하는데, 코트 마진을 그대로 쌓으면 ① 한 쿼터 10명의 합이 늘 0인 제로섬 ② 잘하는 사람이 약한 팀에 배정되는 역선택 ③ **배정이 잘 될수록 두 팀 점수 차가 사라지는** 자기 파괴적 되먹임 때문에 실력과 멀어진다 |
| **선택지** | ① 코트 마진을 그대로 누적 ② **잔차**(실제 점수 차 − 두 팀 실력으로 예상한 점수 차)를 누적하는 실시간 방식(Elo 계열) ③ 모든 쿼터를 한꺼번에 푸는 능형 회귀(RAPM — 여러 선수의 기여를 동시에 추정하는 통계 방법) |
| **결정** | ②를 매 쿼터 쓰고, ③은 기록이 100쿼터 쌓인 뒤 보정용으로 붙인다. 처음 2회 모임의 기록은 반영하지 않는다 |
| **근거 데이터** | 시뮬레이션(가상 동호회 30명, 320쿼터, 40회 반복)에서 실력과의 순위 상관:<br>· 팀을 무작위로 나눌 때 — 원시 마진 0.78 · 잔차 0.88 · RAPM 0.92<br>· **앱의 실제 조건**(추정치로 균형 + 설문) — 원시 마진 **0.61** · 잔차 **0.89** · RAPM 0.92<br>· 팀 균형이 완벽한 극한 — 원시 마진 0.24 · 잔차 0.49 · RAPM 0.68<br>팀을 잘 나눌수록 원시 마진만 무너진다 |
| **결과** | 쿼터를 저장할 때마다 잔차로 실력을 갱신하고, 쿼터를 지우면 팀 전체를 다시 계산해 정확히 되돌린다. `test_rating_simulation.py` 가 "잔차가 원시 마진보다 낫다"는 관계를 푸시마다 검사한다 |

## 3. "같은 팀으로 묶기"를 벌점이 아니라 묶음 단위 탐색으로

| 항목 | 내용 |
| --- | --- |
| **상황** | 매니저가 "이 둘은 꼭 같은 팀"(예: 게스트와 그 게스트를 초대한 사람)을 요구한다. 어떤 배정 기준을 골라도 반드시 지켜져야 한다 |
| **선택지** | ① 묶인 사람이 갈라지면 점수를 깎는 벌점 ② 묶인 사람들을 Union-Find(서로 묶인 사람들을 한 그룹으로 합치는 자료구조)로 한 덩어리로 합쳐, 덩어리 단위로만 팀을 나눈다 |
| **결정** | ② 덩어리 단위로만 나누고 옮긴다. 실행 전에 조건이 가능한지(그룹이 너무 큼 · 묶기와 갈라놓기 충돌 등) 먼저 검사해, 누가 문제인지 알려 준다 |

| **결과** | `test_ranking_assignment.py::test_constraints_always_honored` 가 무작위 묶기 · 갈라놓기 · 사전 배치 조합에서 조건이 항상 지켜지는지, `test_assignment_validation_errors` 가 불가능한 조건이 실행 전에 막히는지 검사한다 |

## 4. AI 에게 역할 판단을 맡기지 않고 설명만 맡긴다

| 항목 | 내용 |
| --- | --- |
| **상황** | 팀원이 전술 편집기에서 움직임을 그리면, 자리마다 역할(볼 핸들러 · 슈터 · 스크리너 등)을 자동으로 붙여야 한다. 처음에는 움직임에서 규칙으로 뽑은 역할을 AI 가 고칠 수 있게 했다 |
| **선택지** | (문서의 O11) ① 프롬프트(AI 에게 주는 지시문)에 기준을 더해 AI 를 개선 ② **AI 는 이유 문장만 쓰고 역할은 규칙 그대로** ③ 지금대로 두고 매니저가 얼마나 고치는지 지켜보기 |
| **결정** | ② — 역할은 규칙이 붙이고 매니저 · 만든 사람이 고친다. AI 는 정해진 역할마다 "이 자리에서 무엇을 하는지" 문장만 쓴다. 대신 규칙을 보강했다 |
| **근거 데이터** | 기본 전술 **22개 × 5자리 = 110자리**를, 전술을 만들 때 붙여 둔 역할과 비교:<br>· 규칙 **65%** (71/110) · AI 가 역할까지 고름 **64%** (70/110) — 차이 없음<br>· AI 가 규칙과 다르게 붙인 23자리 중 11자리는 맞게 고쳤지만 **12자리는 맞던 것을 틀리게** 바꿈<br>· 규칙 보강 후 **82%** (90/110). 단, 규칙을 이 22개를 보며 다듬었으므로 새로 그린 전술에서는 이보다 낮을 수 있다<br>역할을 규칙으로 두면 결과가 매번 흔들리지 않고 테스트로 고정할 수 있다 |
| **결과** | AI 출력에서 역할 칸을 없앴다. 배포 서버 평가에서 22건 모두 역할을 그대로 두고 이유를 썼다. 같은 원칙("판단은 규칙, 문장은 AI")이 배정 설명 · 전술 설명 전체에 적용된다 |
| **출처** | [07 AI 전술 요구사항](07-AI전술-요구사항.md) 13절 O11 · 1.4절 D23, [AI 설명 검증 결과](eval_result.md), `backend/tests/test_team_plays.py` |

## 9. 실력은 수치 대신 등급으로, 등급은 팀 안의 위치로

| 항목 | 내용 |
| --- | --- |
| **상황** | 동호회에서 실력 점수가 공개되면 갈등이 생길 수 있다(기획서 10장의 위험 항목). 그렇다고 매니저까지 모르면 배정 결과를 판단할 근거가 없다 |
| **선택지** | ① 모두에게 수치 공개 ② 매니저는 수치까지, 플레이어는 자기 등급만 ③ 매니저도 등급만 |
| **결정** | ② 매니저는 수치와 근거를 보고, 플레이어는 자기 등급(A~E)만 본다. 등급은 같은 팀 회원 안에서의 위치(상위 10% A · 다음 20% B · 가운데 40% C · 다음 20% D · 하위 10% E)이고, 경기 기록을 저장할 때(일정 단위로) 바뀐다 |
| **근거 데이터** | 수치 근거 없음. 설계 전체가 절대 실력이 아니라 **동호회 안의 상대 순위**를 다룬다는 원칙(기획서 8.1절)을 따랐다 |
