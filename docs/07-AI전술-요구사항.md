## 1. 개요

### 1.1 목적

1. 매니저와 팀원이 **배정 근거를 자연어로** 이해하게 한다 (P2 불만 응대, P3 근거 설명).
2. 그날 짠 블랙/화이트 팀에 **맞는 공격 전술을 추천**하고, 전술판에서 **누가 어느 자리인지** 보여 준다.
3. (2단계) 팀이 **자기 전술을 직접 그려** 추천 후보로 쓰고, 상대 수비 방식을 골라 **수비가 어떻게 따라오는지** 미리 보고, 전술마다 의견을 나눈다.

### 1.2 원칙

- **판단은 규칙과 알고리즘이, 문장은 LLM이, 최종 결정은 매니저가.** LLM은 배정·추천 결과를 바꾸지 않고 설명만 한다.
- **LLM이 없어도 기능이 선다.** 키가 없거나 실패하면 지금의 규칙 기반 설명 문장을 보여 준다.
- **실명과 실력 수치는 밖으로 최소한만.** 외부 모델에는 가명만 보내고, 팀원용 설명에는 실력 수치를 아예 보내지 않는다.

| D10 | 예비 (v1.2) | 자리마다 **같은 전술판 5명 중** 그 역할 점수가 0.6 이상인 다른 사람을 점수 순으로 최대 2명, 괄호로 보여 준다 (예: "볼 핸들러 허재 (예비: 양동근 · 김승현)") |
| D11 | 배정 설명 내용 (v1.3) | 매니저에게는 수치보다 **역할 · 사람 · 조합**으로: 활약이 기대되는 선수(실력 추정 상위 2명과 역할), 호흡이 좋을 조합(상호 지목 · 역할 궁합 — 픽앤롤, 인사이드-아웃 …), 부족한 역할(팀 최고 역할 점수 0.5 미만). 팀원에게는 포지션 이유(선호 순서 · 팀 안 희소 자원) · 기대 역할(역할 점수 1위와 본인 강점) · 호흡 맞출 동료(상호 지목 먼저, 그다음 역할 궁합). 모두 서버 규칙이 정하고 LLM 은 문장으로만 푼다 |
| D12 | 규칙 설명 카드 (v1.3) | 화면에서 뺀다. AI 설명이 실패하거나 키가 없을 때만 같은 카드에 대신 나온다 |
| D13 | 인바운드 | 전술에 `situation`(half_court · inbound)을 둔다. 인바운드는 골밑 베이스라인에서 공을 넣을 때만 쓰므로 **오늘 추천에 넣지 않고** 전술 목록 아래 따로 보여 준다. 공을 넣는 사람은 베이스라인 뒤(y -0.08 ~ 0)에 서고, 전술판은 그런 전술이면 위쪽에 "코트 밖" 띠를 붙인다. 프레스 브레이크(코트 전체 필요)와 모션 오펜스(정해진 순서 없음)는 지금 전술판으로 표현할 수 없어 넣지 않는다 |
| D14 | 막혔을 때의 대안 · 일정 화면 (v1.4) | 전술마다 `counter`(막혔을 때 누구에게 빼는지)를 규칙으로 적어 둔다. 자리는 `{1}`~`{5}` 로 쓰고 그날 배치의 선수 이름(조사는 받침에 맞춤), 일정 없이 보면 "5번" 으로 바꿔 보여 준다 — AI 가 지어내지 않는다. 배정이 확정된 일정 화면이 곧 결과 화면이고, 팀 배정 결과 아래에 이 팀에 맞는 추천 전술을 붙인다(팀원은 내 팀만). 전술 추천 이유(AI 코치)는 팀원에게도 보인다 |
| D15 | 전술판 · 설명 정리 (v1.5) | 추천 전술에서 전술판으로 들어가면 **그 팀 전용**이다 — 블랙/화이트를 바꿔 보는 칸이 없다(팀원은 내 팀, 매니저는 들어온 팀). AI 이유 · 핵심 자리 · 주의할 점 · 막히면을 **"전술 설명" 한 섹션**으로 합쳐 추천 카드와 전술판(전술 이름 아래)에 같은 모양으로 둔다. 일정 없이 열면 전술 소개와 막히면(자리 번호)만 |
| D16 | 수비 시뮬레이션 (v1.6) | **프론트 규칙 계산**(`lib/defense.ts`)으로 한다 — 서버·AI 없이 전술 좌표와 고른 방식만으로. 맨투맨: 수비 i 는 처음에 공격 i 번, 자기 사람과 림 사이 1m(공 가진 사람) ~ 최대 2.8m(공에서 먼 사람) + 공 쪽으로 최대 1.2m 헬프. 지역: 2-3 기본 자리(앞 2 · 뒤 3)가 공 쪽으로 쏠리고 공에 가장 가까운 수비가 달려 나가며, 공 없이 페인트에 들어온 공격수는 가까운 수비가 반쯤 따라붙는다. 경기 기록으로 상대를 추정하지 않는다 — 표본이 없고, "이렇게 막으면 이렇게 움직인다"를 보여 주는 것이 목적이라서 |
| D17 | 스크린 대응 (v1.6) | 스크린과 핸드오프(건네주는 사람이 스크리너)를 만나면 — **스위치**: 두 수비가 마크를 맞바꾼다(맨투맨은 그 뒤로 계속). **스테이**: 스크린에 걸린 수비가 스크린 바깥쪽으로 돌아 한 박자(단계의 30%) 늦게 따라가고, 맨투맨이면 스크리너 수비가 잠깐 튀어나왔다(헤지) 돌아간다. 지역 수비에서는 스크린 자리에 가장 가까운 수비가 걸린 수비다 — 스위치면 옆 수비가 넘겨받고, 스테이면 돌아서 자리로 돌아온다. 전술판에 "스위치/스테이" 표시와 단계 설명 아래 "수비:" 한 줄. (v1.7) **전술마다 고정**: `Play.opp_defense`(man · zone, 비우면 대상 수비에서 — 지역 전술이면 zone, 아니면 man) · `screen_call`(기본 stay). 기본 전술 중 스위치를 깨려고 만든 스페인 픽앤롤 · 포스트 엔트리 + 스플릿 · 박스 인바운드만 switch. 수비 표시는 숫자(1~5)만, 슛하는 단계부터 수비는 제자리 |
| D18 | 팀 전술 (v1.6) | 매니저가 편집기에서 그린 전술을 `team_plays`(시작 위치 · 공 · 단계는 JSON)에 둔다. `play_key` 는 `team:<id>`(전술판 주소는 `team_<id>`). 저장 전 FR-41 재생 가능성 검사를 통과해야 하고, 저장하면 프리셋과 똑같이 그 팀 일정의 추천 후보 · 전술판 · 자리 저장 · AI 전술 설명(C)에 들어간다. 역할을 바꿔 저장하면 일정마다 저장해 둔 그 전술의 자리 배치를 지운다(뜻이 달라지므로) |
| D19 | 역할 정하는 순서 (v1.6) | **규칙 추출 → AI 태깅 → 매니저 수정** 중 마지막 것이 남는다(`role_source` RULE · AI · MANAGER). 규칙은 동작만 읽어 프리셋의 사람 역할과 약 65% 같고, 나머지(킥아웃을 기다리는 코너 등 의도)는 AI 와 매니저가 채운다. 체인 D 에는 선수 정보 없이 자리 이름("왼쪽 코너")과 동작만 보낸다 |
| D20 | 전술 댓글 (v1.6) | 팀 단위 · 전술별(`team_id` + `play_key`). 그 팀 활성 팀원이면 참석과 무관하게 읽고 쓴다. 지우기는 쓴 사람 · 매니저. 500자, 사람당 분당 10개. 알림 · 답글은 없다 |
| D21 | 전술 탭 (v1.7) | 일정 추천을 빼고 전술 목록만 — 별표 전술 → 우리 팀 전술 → 전술 목록 → 인바운드. 그날 추천은 확정된 일정 화면("이 팀에 맞는 전술")에만 있고, 추천 카드는 모두 접힌 채로 시작한다 |
| D22 | 팀 전술 권한 · 별표 (v1.7) | 팀원 누구나 만든다. 고치기 · 지우기는 만든 사람과 매니저. 매니저는 기본 전술 · 팀 전술에 별표를 달고(`tactic_stars`), 별표한 전술은 원래 묶음에서 빠져 맨 위 "별표 전술"에 별표한 순서로 모인다. 팀원에게는 ★만 보인다. 팀 전술을 지우면 별표도 지운다 |

### 4.3 역할 적합도와 전술 추천 — 규칙 (F20)

| ID | 요구사항 | 수용 기준 |

| FR-43 | 선수마다 역할 7개의 점수(0~1)를 7절 식으로 계산한다. 설문이 없는 게스트는 설문 항목을 **그 일정 참석자 평균**으로 채우고 `missing_attrs`에 "설문 없음(게스트)"를 넣는다 | 같은 입력이면 같은 점수. 게스트도 키·포지션은 자기 값으로 반영된다 |

### 4.5 LLM 공통 (F19, F20)

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-48 | **가드레일 모듈** `llm_guard.py`가 모든 체인 호출을 감싼다: 가명화 → 호출 → 출력 검증 → 가명 복원 → 캐시 저장. 실패하면 폴백을 돌려준다 | 9절 규칙을 모두 구현하고 단위 테스트가 있다 |
| FR-49 | 결과는 **내용 기준으로 캐시**한다. 키 = sha256(체인 · 프롬프트 버전(`PROMPT_VERSION`) · 후보안 id · (A) 전략 / (B·C) 팀 번호 · (C) 프리셋 버전 · **가명화한 입력 전체**). 입력이 통째로 키에 들어가므로 선수를 옮기거나, 게스트를 추가하거나, 상호 지목이 바뀌거나, 상대 수비 토글을 바꾸면 새로 만든다. 폴백으로 끝난 결과는 10분(일시적 실패 — 타임아웃 · 429 · 500 · 503 — 는 1분) 뒤 다시 시도한다 | 같은 배정을 다시 열면 LLM을 부르지 않는다. 명단이 바뀌면 다시 부른다 |
| FR-50 | 호출은 **설명 카드가 화면에 뜰 때** 한다(확정할 때 미리 부르지 않음, v1.3). 선수를 옮기는 동안은 1.2초 멈춘 뒤에 부른다. 사용자당 분당 10회 제한을 건다. LLM 호출 타임아웃은 15초 (v1.2 — 8초였으나 Gemini 가 10초 미만 마감을 400 으로 거절하고, 최신 Flash 는 답 전에 생각하는 시간이 있다) | 제한을 넘으면 `429 RATE_LIMITED`. 일시적 오류(타임아웃 · 429 · 500 · 503)면 한 번 더 부르고, 두 번째는 예비 모델(`LLM_FALLBACK_MODEL`)로. 그래도 실패하면 폴백 |

## 7. 역할 점수식

설문 값을 0~1로 바꾼 뒤 가중합한다. 키는 **그 일정 참석자 안의 백분위**.

| 기호 | 출처 | 값 |
| --- | --- | --- |
| `B1:코드` | 공격 옵션 다중선택 | 고르면 1: `CATCH_SHOOT` `PULLUP` `DRIVE_FINISH` `PNR_HANDLER` `PNR_ROLL_POP` `POST_UP` `OFFBALL_CUT` `PUTBACK` |
| `range` | B2 최대 거리 | LAYUP 0 · FLOATER .25 · FT_LINE .5 · THREE .75 · DEEP_THREE 1 |
| `handle` | B3 볼 운반 | NO_DRIVE 0 · LIGHT_PRESS .33 · HALF_COURT .67 · FULL_COURT 1 |
| `height` | 키 | 참석자 내 백분위 |
| `pos:G/F/C` | 가능 포지션 | PG·SG → G, SF·PF → F, C → C |
| `pass`, `stamina` | 기존 6축 | 0~10 → /10 |

| 역할 | 점수 |
| --- | --- |
| ball_handler | .40·handle + .30·B1:PNR_HANDLER + .15·pos:G + .15·pass |
| screener_roll | .35·height + .25·B1:PNR_ROLL_POP + .20·max(B1:PUTBACK, B1:DRIVE_FINISH) + .20·pos:C∨F |
| screener_pop | .35·height + .25·B1:PNR_ROLL_POP + .40·range |
| shooter | .50·range + .35·B1:CATCH_SHOOT + .15·pos:G∨F |
| cutter | .45·B1:OFFBALL_CUT + .35·B1:DRIVE_FINISH + .20·stamina |
| post | .40·height + .45·B1:POST_UP + .15·pos:C∨F |
| spacer | .70·range + .30·B1:CATCH_SHOOT |

- **충족 속성(`matched_attrs`)**: 항의 값 ≥ .5인 것 (예: "3점 거리", "픽앤롤 핸들러").
- **미충족 속성(`missing_attrs`)**: 그 역할에서 가중치가 가장 큰 항이 < .5면 추가.
- 가중치는 상수 한 곳에 두고, 데이터가 쌓이면 조정한다.

## 8. 데이터와 API

### 8.1 좌표 판정 기준

```
미터 변환  X = 15·x, Y = 14·y (y=0 베이스라인)
림         (7.5, 1.575)
3점        Y ≤ 2.99 이면 |X−7.5| ≥ 6.6,  그 위면 림까지 거리 ≥ 6.75
           (v1.0의 "또는" 식은 베이스라인 바로 위 코너 안쪽을 3점으로 잘못 판정해 구간을 나눴다)
페인트     |X−7.5| ≤ 2.45 이고 Y ≤ 5.8
```

테스트 경계: 코너 (0.06, 0.1) → 3점 · (0.07, 0.1) → 미드레인지 · (0.5, 0.60) → 3점(림 거리 ≈ 6.83m) · (0.5, 0.55) → 미드레인지 · (0.5, 0.3) → 페인트.

### 8.2 테이블 (마이그레이션 0020 · 0021)

```
event_play_assignments      -- 그날 팀별 전술 자리 배치 (매니저가 바꿔 저장한 것만. 없으면 자동 추천)
  id BIGINT PK
  event_id   FK events (CASCADE)
  squad_no   SMALLINT            -- 1 블랙 · 2 화이트
  play_key   VARCHAR(40)         -- "preset:high_pnr"
  slot       SMALLINT (1~5)
  player_id  FK players
  assigned_by FK users, created_at
  UNIQUE (event_id, squad_no, play_key, slot)

llm_results                 -- 캐시 + 호출 기록 (0021 — 0020 이 먼저 배포되어 나눴다)
  id BIGINT PK
  chain      VARCHAR(10)         -- A · B · C
  cache_key  VARCHAR(64) UNIQUE  -- sha256 hex
  output     JSONB               -- 복원된 최종 결과 (폴백이면 폴백 내용)
  fallback   BOOLEAN
  fail_reason VARCHAR(40)        -- timeout · error:<예외 이름>:<HTTP 상태> · unknown_alias · unknown_number · leak · schema
  latency_ms INT, model VARCHAR(60), created_at   -- model 은 실제로 답한 모델 버전(응답의 model_name)
                                                  -- 폴백 행은 10분(일시적 실패는 1분) 뒤 다시 시도할 때 갱신
                                                  -- 폴백 행의 output._error 에 공급자 오류 내용 — DB 에만, 응답으로는 내보내지 않는다

  키 없음·꺼짐(disabled)은 기록하지 않는다 — 키를 넣으면 바로 부르도록. 횟수 초과(429)도 기록하지 않는다
```

```
team_plays                  -- 팀이 직접 만든 전술 (0022, FR-57)
  id BIGINT PK
```

팀 전술의 가정한 상대 수비(`opp_defense` · `screen_call`)는 열을 늘리지 않고 `team_plays.body` JSON 에 둔다 (v1.7).

## 9. 가드레일 규칙 (FR-48 상세)

1. **가명화**: 선수 → `P1`…`Pn`(팀·배정 순서로 고정), 팀 → `A`·`B`. 이름이 입력 어디에도 남지 않는다.
2. **가명 복원**: `re.sub(r"P(\d+)(?!\d)", …)`로 숫자를 통째로 읽는다. `P3가`처럼 조사가 붙어도, `P1`과 `P10`이 섞여도 정확히 바뀐다. 바꿀 때 실명 받침에 맞춰 조사(이/가 · 은/는 · 을/를 · 과/와 · 으로/로, 겹조사 포함)를 고친다(`app/core/josa.py`, 프론트는 `lib/josa.ts`).
3. **가명·전술 검사**: 출력의 `P숫자`가 입력에 없거나, 체인 C의 `play_id`가 입력 후보에 없으면 **전체 폐기** (`unknown_alias`).
4. **숫자 검사**: 출력 숫자가 입력 JSON에 없으면 **그 문장만 버린다** (`unknown_number`). 단, 농구 용어(3점, 2점, 1번~5번, 2-3, 3-2, 1-3-1, 1:1, 2:2)는 허용하고, 0.3 · 0.30 · 30%는 같은 값으로 본다. 근거가 모두 버려지면 폴백.
5. **누설 검사(B)**: 출력에 `등급`, `점수`, `순위`, `실력이 (높|낮)` 패턴이 있으면 전체 폐기 (`leak`).
6. **형식 검사**: `with_structured_output` 결과가 스키마를 어기면 폐기 (`schema`). 글자 수 상한을 넘으면 자른다.
7. **재시도**: 일시적 오류(타임아웃 · 429 · 500 · 503)면 한 번 더 부르고, 두 번째는 `LLM_FALLBACK_MODEL`로 부른다.
8. **폴백**: A = `candidate.explanation`(기존 매니저 설명), B = `metrics.player_explanation`, C = 규칙 문장. `fallback=true`로 기록하고 화면에서는 "AI" 표시 없이 보여 준다. C 는 AI 가 빠뜨린 전술만 규칙 문장으로 채우고 순서를 추천 순서로 되돌린다.
9. **로그**: `llm_results`에 체인·성공/폴백·사유·지연·실제 모델 버전. 입력 원문은 저장하지 않는다. 키 없음(`disabled`)과 횟수 초과(429)는 저장하지 않는다.

체인 D(역할 태깅)는 선수 정보가 없어 가명이 비어 있고, 추가 검사는 "자리 1~5 가 하나씩 모두 있는가"다(어기면 `unknown_alias` 사유로 폴백). 역할 값은 스키마의 7개 중 하나여야 한다(`schema`).

처리 순서: 가명화 → 캐시 확인 → 호출(필요하면 재시도) → 형식 → 가명·전술 → 누설(B) → 숫자 → 글자 수 → 체인별 후처리 → 복원 → 저장.

## 10. 체인 입력과 프롬프트

프롬프트와 출력 스키마는 `app/llm/prompts.py`(`PROMPT_VERSION` 4 — 바꾸면 올린다, 캐시 키에 들어간다). temperature 0.3.
**판단은 서버 규칙(`app/services/ai_insight.py`)이 먼저 해서 입력에 넣고**, LLM 은 그 사실을 문장으로만 푼다(D11). 선수는 가명 `P1`…, 팀은 `A`·`B`.

| 판단 | 규칙 |
| --- | --- |
| 기대 역할 (`top_role`) | 7절 역할 점수가 가장 높은 역할 |
| 강점 (`strengths`) | 그 역할에서 본인 설문으로 확인된 속성 최대 2개 (게스트는 없음) |
| 포지션 이유 (`position_why`) | 선호 순서(1순위 · 그 뒤 · 가능 · 팀 구성상) + 팀에 1번·빅맨 가능자가 2명 이하면 그 사실 |
| 호흡 맞출 동료 (`partners`) | 같은 팀에서 서로 같이 뛰고 싶다고 고른 사이 먼저, 그다음 역할 궁합(픽앤롤 · 인사이드-아웃 …) 점수 합이 큰 순, 최대 2명 |
| 부족한 역할 (`gaps`) | 핵심 역할(볼 핸들러 · 슈터 · 포스트 · 롤 빅맨 · 커터) 중 팀 최고 점수가 0.5 미만인 것 |
| 활약 기대 (`key_players`) | 실력 추정 상위 2명과 그 역할 (A 만, 수치는 보내지 않음) |
| 호흡이 좋을 조합 (`pairs`) | 상호 지목 쌍, 모자라면 역할 궁합 상위 |

### 10.1 A — 매니저용

입력: `strategy`, `balance.skill_spread`(두 팀 평균 실력 차), `teams[]{team, size, key_players[]{player, role, strengths}, pairs[]{players, why}, gaps, players[]{player, position, role}, guests_without_skill}`, `constraints_applied{same_team_groups, separate_groups, pinned}`.
출력: `summary`(두 팀 색깔 대비 한 문장, 45자) · `key_players[]`(최대 4) · `chemistry[]`(최대 3) · `gaps[]`(최대 2) · `watch_point`(없으면 빈 문자열).

### 10.2 B — 팀원용 (팀마다 한 번)

입력: `team`, `players[]{id, position, position_why, role, strengths, partners[]{with, why}}`. **실력 값 · 등급 · 순위 없음.**
출력: `messages[]{player, why_position, role, partner}` — 서버는 팀원 전원 것을 저장해 두고 요청한 사람 것만 돌려준다.

### 10.3 C — 전술 추천

입력: `team`, `zone`, `players[]{id, position, height_cm}`, `recommendations[]{play_id, name, summary, fit, slots[]{slot, role, player, strengths, backups}, notes}`. `notes` 는 규칙이 찾은 주의점(설문 없는 게스트 · 점수 50 미만 자리, 최대 2개). 자리별 점수와 막히면은 넣지 않는다. 원본의 `opponent_summary` 는 넣지 않는다(D5).
출력: `one_liner` · `items[]{play_id, reason, key_roles[](최대 3), caution}` — 추천 순서대로.
### 10.4 D — 역할 태깅 (v1.6)

입력: `situation`, `slots[]{slot, start(자리 이름), ball}`, `steps[]{step, caption, actions[]("5번 스크린 → 1번에게 (탑)")}`, `rule_roles[]{slot, role, why}`. 좌표 · 선수 정보 없음. 자리 이름은 `spot_name` — 코너 · 윙 · 탑 · 엘보 · 자유투 라인 · 블록 · 골밑 · 페인트 위쪽 · 미드레인지 · 베이스라인 밖.
출력: `slots[]{slot, role(7개 중 하나), reason(40자)}` — 자리 순서로 되돌린다. 프롬프트 `SYSTEM_D`, 버전 `PROMPT_VERSION_D` 1.
