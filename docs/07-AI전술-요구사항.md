## 1. 개요

### 1.1 목적

1. 매니저와 팀원이 **배정 근거를 자연어로** 이해하게 한다 (P2 불만 응대, P3 근거 설명).
2. 그날 짠 블랙/화이트 팀에 **맞는 공격 전술을 추천**하고, 전술판에서 **누가 어느 자리인지** 보여 준다.

### 1.2 원칙

- **판단은 규칙과 알고리즘이, 문장은 LLM이, 최종 결정은 매니저가.** LLM은 배정·추천 결과를 바꾸지 않고 설명만 한다.
- **LLM이 없어도 기능이 선다.** 키가 없거나 실패하면 지금의 규칙 기반 설명 문장을 보여 준다.
- **실명과 실력 수치는 밖으로 최소한만.** 외부 모델에는 가명만 보내고, 팀원용 설명에는 실력 수치를 아예 보내지 않는다.

### 1.3 범위

| 포함 (1단계) | 제외 (다음 단계에서 검토) |
| --- | --- |
| 전술 좌표·동작 데이터 구조와 판정 유틸 | 커스텀 전술 편집기, 역할 자동 추출, LLM 역할 태깅(체인 D) |
| 프리셋 전술 **8개** (+ O5 6개 · 지역 수비 4개 → 18개) | |

### 1.4 결정 사항

| # | 항목 | 결정 |
| --- | --- | --- |
| D1 | LLM 라이브러리 | **LangChain으로 확정** (v1.1). 나중에 다른 모델로 바꿀 수 있게 하려는 것이 이유다. 모델은 `init_chat_model("<공급자>:<모델명>")` 한 곳에서만 만들고, 체인은 `with_structured_output(Pydantic 스키마)`만 쓴다. 공급자별 기능(Gemini 전용 옵션 등)은 쓰지 않는다 |
| D2 | 모델 | 처음에는 Google AI Studio 무료 등급 Flash 계열. 환경 변수 `LLM_MODEL=google_genai:<모델명>`(기본 `gemini-flash-lite-latest` — 버전 대신 별칭이라 모델이 은퇴해도 깨지지 않고, 설명 문장에는 가벼운 모델이 빠르다), 일시적 오류(503·429·500) 때 두 번째 시도는 `LLM_FALLBACK_MODEL`(기본 `gemini-flash-latest`), 키는 `LLM_API_KEY`(서버 전용, 비우면 공급자 기본 변수 `GOOGLE_API_KEY` 등). **모델을 바꿀 때는 `LLM_MODEL`·`LLM_API_KEY`와 공급자 패키지(`langchain-openai` 등)만 바꾼다** — 키는 `api_key=` 로 넘겨 공급자와 무관하다 |
| D3 | 프리셋 | 1단계 8개 + O5 6개 + 지역 수비 4개 = 18개 (6절). `PRESETS_VERSION` 3. 지역 수비용은 6개 |
| D4 | 전술 이름표 공개 범위 | 그 일정 참석자 전원 |
| D5 | 상대 지역 수비 | 자동 추정하지 않고 매니저 토글 |
| D6 | 무료 등급 데이터 정책 | 도움말에 한 줄 고지 (FR-52) |
| D7 | 우선순위 | 규칙 기반 전술 기능(FR-38~FR-47)을 먼저 완성하고, LLM(FR-48~FR-53)은 그 위에 얹는다 |
| D8 | 추천 방식 (v1.2) | **매니저가 고르지 않는다.** 확정 배정이 있으면 팀마다 적합도 **75 이상**(`FIT_MIN`)인 전술 중 상위 3개를 자동으로 추천하고 자리도 자동으로 채운다. 기준을 넘는 전술이 없으면 추천하지 않는다. 매니저는 전술판에서 자리를 바꿔 저장할 수 있고(최종 결정은 사람이), 빈 목록을 저장하면 추천 배치로 돌아간다 |
| D9 | 공개 범위 (v1.2) | 그날 참석자는 추천 전술 · 자리 배치 · 예비를 본다. 자리별 점수 · 충족/미충족 속성 · 벤치 교체 후보는 매니저만 |
| D10 | 예비 (v1.2) | 자리마다 **같은 전술판 5명 중** 그 역할 점수가 0.6 이상인 다른 사람을 점수 순으로 최대 2명, 괄호로 보여 준다 (예: "볼 핸들러 허재 (예비: 양동근 · 김승현)") |
| D11 | 배정 설명 내용 (v1.3) | 매니저에게는 수치보다 **역할 · 사람 · 조합**으로: 활약이 기대되는 선수(실력 추정 상위 2명과 역할), 호흡이 좋을 조합(상호 지목 · 역할 궁합 — 픽앤롤, 인사이드-아웃 …), 부족한 역할(팀 최고 역할 점수 0.5 미만). 팀원에게는 포지션 이유(선호 순서 · 팀 안 희소 자원) · 기대 역할(역할 점수 1위와 본인 강점) · 호흡 맞출 동료(상호 지목 먼저, 그다음 역할 궁합). 모두 서버 규칙이 정하고 LLM 은 문장으로만 푼다 |
| D12 | 규칙 설명 카드 (v1.3) | 화면에서 뺀다. AI 설명이 실패하거나 키가 없을 때만 같은 카드에 대신 나온다 |

## 2. 용어

| 용어 | 뜻 |
| --- | --- |
| 전술(play) | 공격 5명의 시작 위치와 시간순 동작 목록 |
| 프리셋 | 앱에 미리 넣어 둔 전술. 코드 파일 한 곳이 정본 (`play_key = "preset:<이름>"`) |
| 슬롯 | 전술 안의 자리 번호 1~5 |
| 역할 | 슬롯이 맡는 일. `ball_handler` · `screener_roll` · `screener_pop` · `shooter` · `cutter` · `post` · `spacer` |
| 이름표 | 그날 블랙/화이트에서 슬롯마다 앉힌 선수 |
| 적합도 | 슬롯 5개에 선수를 가장 잘 앉혔을 때의 역할 점수 평균 × 100 |
| 가명 | LLM에 보내는 선수 이름 대신 쓰는 `P1`…`Pn`, 팀은 `A`·`B` |
| 폴백 | LLM이 실패했을 때 대신 보여 주는 기존 규칙 기반 문장 |

## 4. 기능 요구사항

기존 FR-01~FR-37에 이어 번호를 붙인다. 기능 번호는 F19(AI 배정 설명) · F20(전술 추천) · F21(전술판).

### 4.1 전술 데이터와 판정 (F21)

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-38 | 전술은 **좌표가 아니라 동작의 순서**로 저장한다. 시작 위치 5개, 공을 가진 슬롯, 단계 목록(한 단계 안의 동작은 동시에 재생), 슬롯별 역할, 대상 수비(`man`·`zone`·`any`)를 가진다 | Pydantic 모델로 검증되고, 필수 값이 빠지면 저장·로드가 실패한다 |
| FR-39 | 동작 종류는 `move`(이동) · `dribble`(드리블 이동) · `pass`(패스) · `screen`(스크린) · `cut`(컷) · `handoff`(핸드오프) · `shot`(슛) 일곱 가지다 | 다른 값은 거부된다 |
| FR-40 | 좌표는 0~1로 저장하고, 판정은 **FIBA 하프코트 15m × 14m**로 환산해서 한다. `is_three` · `is_paint` · `zone_of`(3점 밖 / 미드레인지 / 페인트) 유틸을 파이썬과 TS에 같은 상수로 둔다 | 8.1의 경계값 테스트를 통과한다 |
| FR-41 | 전술은 **재생 가능성 검사**를 통과해야 한다. ① 한 단계에 공 동작(`dribble`·`pass`·`handoff`·`shot`)은 하나뿐 ② 공 동작은 그 단계를 시작할 때 공을 가진 슬롯만 ③ 공을 가진 슬롯은 `move`·`cut` 대신 `dribble`로 움직인다 ④ 한 슬롯은 한 단계에 동작 하나 ⑤ `pass`·`handoff`를 받은 슬롯이 다음 단계부터 공을 가진다 ⑥ 슛 뒤에는 단계가 없고, 마지막 단계는 `shot` 또는 `pass`로 끝난다 | 프리셋 18개가 모두 통과하고, 규칙을 어긴 예제는 어느 단계의 무슨 문제인지 메시지와 함께 거부된다 |

### 4.2 프리셋 (F21)

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-42 | 프리셋 8개(6절)를 코드 파일 한 곳에 둔다. 각 프리셋은 이름, 한 줄 설명, 대상 수비, 시작 위치, 3~6단계, 슬롯별 역할을 가진다 | 8개 모두 FR-41 검사 통과. `presets_version` 상수가 있다 |

### 4.3 역할 적합도와 전술 추천 — 규칙 (F20)

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-43 | 선수마다 역할 7개의 점수(0~1)를 7절 식으로 계산한다. 설문이 없는 게스트는 설문 항목을 **그 일정 참석자 평균**으로 채우고 `missing_attrs`에 "설문 없음(게스트)"를 넣는다 | 같은 입력이면 같은 점수. 게스트도 키·포지션은 자기 값으로 반영된다 |
| FR-44 | 한 팀(블랙 또는 화이트, **6~10명**)과 전술 하나에 대해, 선수 5명을 골라 슬롯에 앉히는 **최적 배치**를 구한다. 5슬롯 비트마스크 DP(상태 32 × 선수 n)로 푼다. 슬롯마다 **교체 후보**(그 슬롯에 앉혔을 때 점수가 가장 높은 **벤치** 선수, 팀이 딱 5명이면 없음)도 낸다. 로테이션으로 쉬는 사람이 누구 자리를 받으면 좋은지 알려 주려는 것 | 완전 탐색 결과와 적합도가 같다(정답 기준 테스트). 전술 8개 × 두 팀 계산이 100ms 안쪽 |
| FR-45 | 그날 확정 배정이 있으면 팀마다 **적합도 75 이상인 전술 중 상위 3개**를 자동으로 추천한다(D8). "상대가 지역 수비를 써요"를 켜면 `zone`·`any` 전술만, 끄면 `man`·`any` 전술만 후보로 삼는다(보기 전환, 누구나) | 결과에 전술별 적합도, 자리별 선수·역할·예비(D10)가 들어 있고, 매니저에게는 점수·충족/미충족 속성·벤치 교체 후보가 더 있다. 기준을 넘는 전술이 없으면 빈 목록 |

### 4.4 전술 탭 · 전술판 · 이름표 (F21)

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-46 | 팀 화면 탭을 **일정 · 기록 · 전술 · 팀원**으로 바꾼다. 전술 탭은 다가오는 확정 배정이 있으면 위에 그날 추천 전술(참석자 누구나, 내 팀 먼저), 아래에 전체 프리셋 목록을 보여 준다. 배정 결과 화면(S-14)에도 "오늘 추천 전술" 목록을 둔다 | 확정 배정이 없거나 참석자가 아니면 목록만. 새 달 첫 방문 시 기록 탭 우선 규칙은 그대로 |
| FR-47 | 전술판은 하프코트 위에 공격 5명(번호 동그라미, 그날 팀 색)과 공을 그리고, **처음 · 이전 단계 · 재생/일시정지 · 다음 단계 · 속도(0.5×/1×/2×)** 로 단계별 재생한다. 그날 일정으로 열면 자리 배치(자동 추천, 매니저가 저장했으면 그 배치)와 자리마다 예비를 보여 준다. 매니저는 동그라미를 눌러 사람을 바꿔 저장하거나 추천 배치로 되돌린다 | 스크린은 T자, 패스는 점선과 공 이동, 컷은 굵은 화살표로 그리고 범례를 한 줄로 둔다. `prefers-reduced-motion`이면 애니메이션 없이 단계만 바뀐다. 매니저가 바꾼 배치는 일정·팀·전술별로 저장된다 |

### 4.5 LLM 공통 (F19, F20)

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-48 | **가드레일 모듈** `llm_guard.py`가 모든 체인 호출을 감싼다: 가명화 → 호출 → 출력 검증 → 가명 복원 → 캐시 저장. 실패하면 폴백을 돌려준다 | 9절 규칙을 모두 구현하고 단위 테스트가 있다 |
| FR-49 | 결과는 **내용 기준으로 캐시**한다. 키 = sha256(체인 · 후보안 id · 정렬한 [팀 번호, 선수 id, 배정 포지션] · 전략 · 입력 형식 버전 · 프리셋 버전(C만) · 대상). 확정 뒤 선수를 옮기거나 게스트를 추가하면 새로 만든다 | 같은 배정을 다시 열면 LLM을 부르지 않는다. 명단이 바뀌면 다시 부른다 |
| FR-50 | 호출은 **설명 카드가 화면에 뜰 때** 한다(확정할 때 미리 부르지 않음, v1.3). 선수를 옮기는 동안은 1.2초 멈춘 뒤에 부른다. 사용자당 분당 10회 제한을 건다. LLM 호출 타임아웃은 15초 (v1.2 — 8초였으나 Gemini 가 10초 미만 마감을 400 으로 거절하고, 최신 Flash 는 답 전에 생각하는 시간이 있다) | 제한을 넘으면 `429 RATE_LIMITED`. 타임아웃이면 폴백 |

## 7. 역할 점수식

설문 값을 0~1로 바꾼 뒤 가중합한다. 키는 **그 일정 참석자 안의 백분위**.

| 기호 | 출처 | 값 |
| --- | --- | --- |
| `B1:코드` | 공격 옵션 다중선택 | 고르면 1: `CATCH_SHOOT` `PULLUP` `DRIVE_FINISH` `PNR_HANDLER` `PNR_ROLL_POP` `POST_UP` `OFFBALL_CUT` `PUTBACK` |
| `range` | B2 최대 거리 | LAYUP 0 · FLOATER .25 · FT_LINE .5 · THREE .75 · DEEP_THREE 1 |
| `handle` | B3 볼 운반 | NO_DRIVE 0 · LIGHT_PRESS .33 · HALF_COURT .67 · FULL_COURT 1 |
| `height` | 키 | 참석자 내 백분위 |
| `pos:G/F/C` | 가능 포지션 | PG·SG → G, SF·PF → F, C → C |
| `pass`, `stamina` | 기존 6축 | 0~10 → /10 |

| 역할 | 점수 |
| --- | --- |
| ball_handler | .40·handle + .30·B1:PNR_HANDLER + .15·pos:G + .15·pass |
| screener_roll | .35·height + .25·B1:PNR_ROLL_POP + .20·max(B1:PUTBACK, B1:DRIVE_FINISH) + .20·pos:C∨F |
| screener_pop | .35·height + .25·B1:PNR_ROLL_POP + .40·range |
| shooter | .50·range + .35·B1:CATCH_SHOOT + .15·pos:G∨F |
| cutter | .45·B1:OFFBALL_CUT + .35·B1:DRIVE_FINISH + .20·stamina |
| post | .40·height + .45·B1:POST_UP + .15·pos:C∨F |
| spacer | .70·range + .30·B1:CATCH_SHOOT |

- **충족 속성(`matched_attrs`)**: 항의 값 ≥ .5인 것 (예: "3점 거리", "픽앤롤 핸들러").
- **미충족 속성(`missing_attrs`)**: 그 역할에서 가중치가 가장 큰 항이 < .5면 추가.
- 가중치는 상수 한 곳에 두고, 데이터가 쌓이면 조정한다.

## 9. 가드레일 규칙 (FR-48 상세)

1. **가명화**: 선수 → `P1`…`Pn`(팀·배정 순서로 고정), 팀 → `A`·`B`. 이름이 입력 어디에도 남지 않는다.
2. **가명 복원**: `re.sub(r"P(\d+)(?!\d)", …)`로 숫자를 통째로 읽는다. `P3가`처럼 조사가 붙어도, `P1`과 `P10`이 섞여도 정확히 바뀐다.
3. **가명·전술 검사**: 출력의 `P숫자`가 입력에 없거나, 체인 C의 `play_id`가 입력 후보에 없으면 **전체 폐기** (`unknown_alias`).
4. **숫자 검사**: 출력 숫자가 입력 JSON에 없으면 **그 문장만 버린다** (`unknown_number`). 단, 농구 용어(3점, 2점, 1번~5번, 2-3, 3-2, 1-3-1, 1:1, 2:2)는 허용하고, 0.3 · 0.30 · 30%는 같은 값으로 본다. 근거가 모두 버려지면 폴백.
5. **누설 검사(B)**: 출력에 `등급`, `점수`, `순위`, `실력이 (높|낮)` 패턴이 있으면 전체 폐기 (`leak`).
6. **형식 검사**: `with_structured_output` 결과가 스키마를 어기면 폐기 (`schema`). 글자 수 상한을 넘으면 자른다.
7. **폴백**: A = `candidate.explanation`(기존 매니저 설명), B = `metrics.player_explanation`, C = 규칙 문장. `fallback=true`로 기록하고 화면에서는 "AI 설명" 표시 없이 보여 준다.
8. **로그**: `llm_results`에 체인·성공/폴백·사유·지연·모델. 입력 원문은 저장하지 않는다.

## 10. 체인 입력과 프롬프트

프롬프트 본문은 원본 명세 8절 A·B·C를 쓰되 아래를 바꾼다. temperature 0.3.

### 10.1 A — 매니저용

입력: 전략, 팀별 가명 목록, `metrics`의 `squad_avg_skill` · `skill_spread` · `position_coverage` · `guest_count_per_squad` · `unknown_skill_per_squad` · `terms`, 팀별 평균 키, 적용된 제약(묶기·갈라놓기·사전 배치, 인원을 벌렸으면 그 사실), 같은 팀이 된 상호 지목 쌍. 출력 형식은 원본 A 그대로.

### 10.2 B — 팀원용 (팀마다 한 번)

입력: 팀 가명 목록과 배정 포지션, 규칙으로 만든 팀 특징 태그("180cm 이상 3명", "가드 3명" 등), 선수별 상호 지목 상대. **실력 값 없음.** 출력 형식을 바꾼다.

```json
{ "messages": [ { "player": "P3", "message": "2~3문장, 120자 이내" } ] }
```

### 10.3 C — 전술 추천

입력: FR-45 결과(상위 3개, 슬롯별 가명·역할·충족/미충족), 우리 팀 가명별 포지션·키, 지역 수비 토글 값. 원본의 `opponent_summary`는 넣지 않는다(D5). 출력 형식은 원본 C 그대로.
