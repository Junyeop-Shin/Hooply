# 화면 리디자인 — B안 "코트 나이트" (2026-11)

"UI를 확 세련되게" 바꾸자는 요청으로 홈 화면 방향 시안 세 가지(A 맑게 · B 코트 나이트 · C 모노 라인)를 만들었고, **B** 로 정했다(2026-11-22). 이 문서는 B의 규칙과, 전 화면에 적용하는 순서 · 확인 방법을 적는다. 화면별 요소는 `docs/02` 가 정본이고, 이 문서는 **모양의 규칙**만 다룬다.

- **바꾸는 것** — 색 · 글꼴 · 모서리 · 화면 위쪽(머리)의 구성.
- **바꾸지 않는 것** — 기능 · 문구 · 화면 순서. 버튼과 링크의 이름(스크린리더 · E2E 가 찾는 이름)도 그대로 둔다. 예외는 시안에 있던 하단 메뉴 "팀" 하나(docs/10 X-1).
- **새로 두는 버튼 · 링크의 이름** — 이미 있는 이름을 품지 않게 짓는다. 홈 머리의 프로필 버튼을 "내 프로필"로 지었더니 하단 메뉴의 "프로필"과 이름으로 구분되지 않아 E2E 가 걸렸다 → "내 정보".

---

## 1. 규칙

| # | 규칙 | 내용 |
| --- | --- | --- |
| 1 | **색** | 어두운 남색 머리(`bar` #0d1a33) + 밝은 회색 바탕(`canvas` #f3f4f6) + 흰 카드. 강조는 오렌지 하나 — 밝은 면에서는 `brand`(#c24e0e), 남색 면에서는 `bar-accent`(#ff8340, 그 위 글자 `on-bar-accent` #24100a) |
| 2 | **숫자** | 그 화면의 주인공 숫자(D-day · 날짜 · 점수 · 인원)는 좁고 굵은 숫자체 `font-display`(Barlow Condensed)로 크게. 날짜는 `11.29 SUN`, 남은 날은 `D-7` |
| 3 | **머리(히어로)** | 핵심 숫자가 있는 화면에만 남색 머리를 크게 쓴다: 홈(다음 경기) · 일정(날짜 · 참석) · 팀(팀원 수) · 확정 결과(내 팀) · 경기 기록(점수) · 기록(순위). 배경에 옅은 코트 선(`components/court-lines.tsx`). 설문 · 입력 화면은 밝고 단순한 상단 바만 |
| 4 | **카드** | 흰 면, 모서리 14px(`rounded-2xl`), 그림자 없음, 옅은 선. 목록은 카드 사이 8px |
| 5 | **칩** | 각진 6px. 상태는 색으로 구분하되(완료 초록 · 주의 호박색), **내가 할 일**("미응답")은 남색 채움 |
| 6 | **하단 메뉴** | 남색 바탕, 홈 · 팀 · 프로필. 활성은 오렌지. "팀"은 기본 팀(없으면 첫 팀)으로, 팀이 없으면 팀 코드 가입 화면으로 |
| 7 | **영어 표기** | `NEXT GAME` 과 요일 세 글자(`SUN`)처럼 짧은 라벨만. 화면에 보이는 영어 옆에는 스크린리더용 한글을 함께 둔다("다음 일정") |
| 8 | **어두운 화면** | 같은 토큰 이름으로 값만 바뀐다(`index.css`). 머리는 바탕과 거의 같은 남색이 되고, 카드에는 선이 남는다 |

글꼴은 숫자 · 영문용 Barlow Condensed 하나만 앱에 함께 싣는다(외부 요청 없음, 굵기 600 · 700). 한글은 기기 글꼴을 그대로 쓴다 — 한글 웹폰트는 용량이 커서 "처음 50초"에 더 얹지 않는다.

## 2. 적용 순서

| 단계 | 범위 | 상태 |
| --- | --- | --- |
| ① 기반 + 자주 보는 화면 | 색 토큰 · 숫자 글꼴 · 카드 · 칩 · 제목 · 하단 메뉴(팀 추가) · 코트 선 / 홈(S-04) · 일정(S-10) · 팀(S-07) · 일정 줄(`EventRow`) | 구현 (2026-11-22) |
| ② 경기 날 화면 | 팀 배정 실행 · 결과 · 확정(S-12 ~ S-14) · 경기 기록(S-15) · 투표(S-16) | 예정 |
| ③ 나머지 | 프로필 · 기록 탭 · 리더보드 · 선수 지표 · 전술 · 설문 · 가입 · 팀 관리 · 도움말 · 로그인 | 예정 |

①의 공통 부품(카드 · 칩 · 버튼 · 제목 · 하단 메뉴)은 모든 화면이 같이 쓰므로, ①이 끝나면 ② · ③의 화면도 색과 모서리는 이미 따라와 있다. ② · ③에서는 각 화면의 머리와 숫자를 손본다.

## 3. 확인 방법

- 타입 검사 · 린트 · Vitest · E2E 가 그대로 통과한다 — 이름으로 찾는 테스트라 모양이 바뀌어도 깨지지 않아야 한다. 깨지면 이름이나 동작을 건드린 것이다.
- 휴대폰 크기(390×844)로 전 화면을 밝은 · 어두운 화면에서 찍어 훑는다(가로 넘침 0, 겹침 0).
- 글자 대비 4.5:1 이상(큰 숫자는 3:1). 새로 쓰는 색 조합은 계산해서 확인한다.
- 단계마다 실제 앱 화면을 보여 주고 확인받은 뒤 푸시한다.
