# 개선점 정리 — 2026-11 (코드 · 기능 · UI · UX)

docs/09(사용성 점검)의 항목을 모두 정리한 뒤, 코드 전체를 다시 훑어 **① 코드 최적화 ② 기능 ③ UI 디자인 ④ UX** 네 갈래로 남은 개선점을 모았다. 무엇을 할지 고르기 위한 목록이고, 고친 항목은 ✅ 로 표시했다(0-1절).

- **보는 기준** — 팀원들이 앱에 들어오는 것부터 부담스러워한다(단톡방 링크를 누르는 정도). 그래서 "팀원이 앱을 열 일을 줄이는가 · 한 번 열었을 때 빨리 끝나는가 · 매니저의 매주 일을 줄이는가"를 먼저 봤다.
- **주어진 조건** — 서버가 Render 무료 등급이라 잠들었다 깨어날 때 첫 요청이 약 50초 걸린다(2026-11-22 실측 50.9초, 깨어난 뒤 0.3~0.4초). 깨우는 시간 자체는 코드로 못 줄인다. 체감을 줄이는 선택지만 1-3절에 따로 적었다.
- **확인 방법** — 코드는 직접 읽고 줄 번호를 적었다. 화면은 로컬 데모 데이터로 휴대폰 크기(390×844) 59장(밝은 화면 51 · 어두운 화면 8)을 찍어서 봤다. 숫자는 이 PC에서 잰 값이다. 추정은 "추정"이라고 적었다.
- **크기** — S: 반나절 안 · M: 하루 안팎 · L: 며칠.

### 1-4. 확인했고 손댈 필요 없는 것

- 요청마다 고정으로 나가는 쿼리는 1~3개(`api/deps.py`), 자주 쓰는 API 는 쿼리 수 상한 테스트가 지킨다
- 응답 압축(gzip) 켜져 있음(설문 7.2KB → 2.3KB), 프로필 사진은 1년 캐시(`api/v1/auth.py:359`)
- 화면 데이터 캐시 설정이 적절(1분 신선 · 30분 보관 · 탭 복귀 때 다시 안 받음, `queryClient.ts`)
- 화면 묶음: 화면별로 나눠 받고, 라이브러리는 7개뿐(공통 묶음 약 270KB, 압축 85KB). 웹폰트를 받지 않는다(기기 글꼴)
- 화면 코드에 `any` · 억지 형변환 0건
- DB 인덱스 · 값 범위 검사 · 요청 제한은 이전 하드닝(0025 · 0026)에서 정리됨
